# Documentation

Rational Unified Process (RUP) artefacts with the **4+1 architectural view model** (Kruchten, 1995).

| Artefact | What it answers |
|---|---|
| [Vision](rup/01-vision.md) | What problem, for whom, what is in and out of scope |
| [Software Requirements Specification](rup/02-requirements.md) | Functional and non-functional requirements, with traceability |
| [Software Architecture Document](architecture/00-software-architecture-document.md) | Goals, constraints, mechanisms; entry point to the views |
| [Scenarios view (+1)](architecture/01-scenarios-view.md) | Use cases and the sequences that realise them |
| [Logical view](architecture/02-logical-view.md) | Layers, ports and adapters, classes |
| [Process view](architecture/03-process-view.md) | Processes, threads, protocols, timing, failures |
| [Development view](architecture/04-development-view.md) | Repository layout, dependency rules, build and test |
| [Physical view](architecture/05-physical-view.md) | Hardware nodes, wiring, deployment on the robot |
| [SOLID in this project](architecture/06-solid-principles.md) | Each principle mapped to the code |
| [Architecture Decision Records](architecture/adr/README.md) | Why each significant choice was made |
| [Test plan](rup/03-test-plan.md) | Test levels, cases and field checklist |
| [Glossary](rup/04-glossary.md) | Terms |

Diagrams use Mermaid, which GitHub renders directly.
